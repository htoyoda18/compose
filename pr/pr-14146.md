# PR #14146: fix(publish): warn when push falls back from OCI 1.1 to OCI 1.0

https://github.com/docker/compose/pull/14146

## 問題

`docker compose publish` は、レジストリがOCI 1.1形式のマニフェストを拒否した場合、
黙ってOCI 1.0形式にフォールバックして再送信していた。ユーザーには「フォールバック
した」という事実が一切伝わらず、意図せず古いフォーマットで保存されていることに
気付けない。

`internal/oci/push.go` の `PushManifest` にはこれを示す
`// TODO(milas): show a warning here (won't work with logrus)` というコメントが
残っており、「`internal/oci` パッケージは意図的に`logrus`に依存していない」ため
警告を出す手段が無いまま放置されていた。

## 原因

`internal/oci` はログライブラリに依存しない設計方針のため、フォールバックの
事実をこのパッケージ内で直接ログ出力することはできない。一方、呼び出し元の
`pkg/compose/publish.go` は既に`logrus`に依存しているため、「フォールバックした
かどうか」という**事実だけ**を`PushManifest`の戻り値として呼び出し元に伝え、
実際の警告表示は`publish.go`側の責務にする必要があった。

この設計変更を実装する過程で、2回のレビュー往復があった:

1. 最初のバージョンでは`PushManifest`が生の`api.OCIVersion`（実際に使われた
   バージョン）を返し、呼び出し側で`options.OCIVersion == "" && usedOCIVersion ==
   api.OCIVersion1_0`という2値比較で「フォールバックしたか」を再計算していた。
   レビューで「呼び出し側が本当に必要としているのは`bool`一つなのだから、
   `PushManifest`側で直接`bool`を返すべき」と指摘された。
2. 次に、フォールバック時の警告を`logrus.Warn`で出すようにしていたが、
   `docker compose publish`はTTY環境で独自の進捗レンダラー（`s.events`経由の
   イベントバス）を使って状態表示しており、`logrus.Warn`はこのレンダラーを
   経由しないため通常のターミナルでは画面に一切出ない、と指摘された。

## 修正内容

- `internal/oci/push.go`: `PushManifest`のシグネチャを
  `(v1.Descriptor, error)` → `(v1.Descriptor, bool, error)` に変更。
  2番目の戻り値`didFallback`は「OCI 1.1が拒否されOCI 1.0で再送信したか」を
  直接表す。TODOコメントを削除し、フォールバック発生箇所で`true`を返すように。
- `pkg/compose/publish.go`:
  - `pushComposeArtifact`も同様に`(bool, error)`を返すよう変更し、
    `didFallback`を`publish`まで伝播。
  - `publish`は`didFallback`に応じて`s.events.On(...)`に渡す
    `Text`/`Status`を切り替え、フォールバック時は
    `"published (registry rejected OCI 1.1; fell back to OCI 1.0)"` /
    `api.Warning`として、通常の完了イベントと**同じイベントバス**に
    折りたたんで報告する（`logrus.Warn`は使わない）。

## 変更ファイルとその内容

```
internal/oci/push.go   | 13 ++  -9
pkg/compose/publish.go | 16 ++  -10
```

- `internal/oci/push.go`: `PushManifest`が`didFallback bool`を返すように変更。
  各早期return箇所（レイヤーpush失敗、明示バージョン指定時など）は`false`、
  実際にOCI 1.1→1.0フォールバックが発生した分岐だけ`true`を返す。
  関数コメントに戻り値の意味（`err == nil`のときのみ意味を持つ）を明記。
- `pkg/compose/publish.go`: `pushComposeArtifact`が`didFallback`を
  `PushManifest`から受け取って呼び出し元に伝播。`publish`はこれを見て
  完了イベントの`Text`/`Status`を`"published"`/`api.Done`か
  `"published (...)"`/`api.Warning`のどちらかに出し分ける。

## この session の [pr-review-patterns.md](../document/pr-review-patterns.md) 上の位置付け

このPRは以下2つのテーマの実例:

- テーマ③(API設計): 「呼び出し側が欲しい答え」ではなく「たまたま持っている
  データ」を返していた最初の実装を、レビューで直接`bool`を返す設計に修正。
- テーマ④(出力経路): `logrus.Warn`がTTY進捗表示を経由しないという、
  アプリの表示基盤に関する指摘を受けて`s.events`経由に修正。
