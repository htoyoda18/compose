# PR #14310: fix(down): keep tearing down when listing retained hook containers fails

https://github.com/docker/compose/pull/14310

- 状態（2026-10-18）: OPEN。ndeloof が 10-13 に APPROVED。fork からの PR なので、CI を動かすのにメンテナの承認待ち

## 問題

`docker compose down` は、失敗して残された pre_start フック用のコンテナ（調査用に残したもの）を掃除する。
その一覧の取得（`ContainerList`）が失敗すると、`down` 全体がそこでエラー終了していた。
その後に続くネットワーク・ボリューム・イメージの削除がまるごと飛ばされ、プロジェクトのリソースが残ってしまう。

## 原因

- `removePreStartHookContainers` の doc コメントには「個々の削除の失敗は warn で記録し、ティアダウンは止めない」と書かれていた。
  実際、コンテナの**削除**の失敗は `logrus.Warnf` で流していた。
- ところが、その前の**一覧の取得**の失敗だけは `return err` していた。呼び出し元の `down` も、それをそのまま `return err` していた。
- 「後片付けの補助的な処理が失敗しても、本体のティアダウンは止めない」という方針が、一覧の取得のところだけ守られていなかった。
- この不整合は、フック出力の PR [#14091](https://github.com/docker/compose/pull/14091) のレビューで、ndeloof が「list-failure aborting teardown」として残した follow-up の 1 つ（「別の PR で出してよい」と明言）。

## 修正内容

- 一覧の取得に失敗したら、削除の失敗と同じく `logrus.Warnf` で警告を出し、`continue` で次のフィルタに進む。
- これで `removePreStartHookContainers` はエラーを返す場面が無くなったので、戻り値の `error` を外した。呼び出し元の `if err := ...; err != nil { return err }` も、ただの呼び出しにした。
- doc コメントを「Listing and removal failures are logged at warn level and do not abort teardown.」に直し、実装と合わせた。

## 変更ファイルとその内容

```
pkg/compose/down.go      |  5 ++  -7
pkg/compose/down_test.go | 34 ++++
```

- `pkg/compose/down.go`:
  - `down` から `removePreStartHookContainers` を呼ぶところで、エラーを見なくなった（戻り値が無くなったため）
  - `removePreStartHookContainers` のシグネチャから `error` を外した
  - `ContainerList` の失敗を `Warnf` + `continue` にした
  - 最後の `return nil` を削除した
  - doc コメントを直した
- `pkg/compose/down_test.go`: `TestDownHookContainerListFailureIsNonFatal` を追加。
  - mock の API クライアントで、フック用コンテナの一覧取得（`hookFilterListOpt()`）だけが `errors.New("daemon busy")` で失敗するようにする。
  - その後に、ネットワークの一覧取得（通常のものと、relay 用のもの）が**呼ばれること**を `EXPECT()` で要求する。
  - `Down` がエラーを返さないことを確かめる。
  - 修正前のコードでは、ネットワークの一覧取得まで進まないので、このテストは失敗する。
  - 隣の、削除の失敗を扱う `TestDownHookContainerRemovalFailureIsNonFatal` と対になるテスト。

## pr-review-patterns.md 上の位置付け

コードへの指摘は無く、承認された。学びはプロセスの側にある（[next-tasks.md の 5](../document/tracking/next-tasks.md) にも記録）。

- 承認の後、自分で main をブランチに merge したため、ndeloof が設定してくれた auto-merge が外れた。
  その後、main への rebase で、承認時と同じ 1 コミットに戻した（`git range-diff` で中身が変わっていないことを確認）。
- fork からの PR は、push し直すたびに、CI を動かすのにメンテナの承認が要る。**承認をもらったら、ブランチはできるだけ触らない**。
