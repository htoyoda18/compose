# PR #14120: test(build): re-enable wrong ssh key id test

https://github.com/docker/compose/pull/14120

## 問題

`pkg/e2e/build_test.go` の `TestBuildSSH` 内にある「build failed with wrong ssh key id from CLI」
サブテストが、`FIXME disabled waiting for https://github.com/moby/buildkit/issues/5558` という
コメントとともにコメントアウトされ、無効化されたままになっていた。

### 「build failed with wrong ssh key id from CLI」サブテストの内容

このサブテストは、`docker compose build --ssh` に**Dockerfileが要求しているものと違うid**を
渡した場合に、ビルドが正しく失敗することを確認するテスト。

- テスト対象の `fixtures/build-test/ssh/Dockerfile` には
  `RUN --mount=type=ssh,id=fake-ssh,required=true ...` という記述があり、
  `fake-ssh` というidのSSHエージェントマウントを必須としている
- `compose-without-ssh.yaml` はcompose file側で`ssh:`を宣言していないため、
  CLI側の`--ssh`フラグで補う必要がある
- テストは意図的に `--ssh wrong-ssh=./fixtures/build-test/ssh/fake_rsa` という
  **間違ったid（`wrong-ssh`）** を指定してビルドを実行し、
  - `ExitCode: 1`
  - 標準エラーに `unset ssh forward key fake-ssh`

  が返ることを期待している。つまり「Dockerfileが要求する`fake-ssh`というidが
  渡されていない」ことをbuildkitが正しく検出し、ビルドを失敗させる挙動を保証するテスト。

## 原因

`moby/buildkit#5558`（`--no-cache` が無視されてしまう regression。buildkit v0.17.2で混入）は
2024年12月時点で既にfix・closeされていた。一方で`go.mod`で現在vendoringしているbuildkitは
v0.26.3であり、このissueが解消されたバージョンより十分新しい。つまりFIXMEコメントが指す
ブロッカーはとうに解消済みだったにもかかわらず、サブテストが再有効化されずコメントアウトの
まま放置されていた。

## 修正内容

- コメントアウトされていたサブテストのコードブロックを復元し、`t.Run` を通常のテストとして
  再度有効化
- ローカルで `go test -tags e2e ./pkg/e2e/ -run TestBuildSSH -v` を実行し、再有効化した
  サブテストがpassすることを確認（3回連続実行してflakyでないことも確認済み）
- ビルド出力が期待通り `unset ssh forward key fake-ssh` エラーになることを確認
