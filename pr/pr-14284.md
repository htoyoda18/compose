# PR #14284: fix(models): check the model listing error and keep pull errors per goroutine

https://github.com/docker/compose/pull/14284

- 状態（2026-11-05）: OPEN、CHANGES_REQUESTED（glours）。10-27 の返信（model-runner 1.2.9 が出た、CI の実行承認の依頼）に返事無し

## 問題

`pkg/compose/model.go` の `ensureModels` に、前からある問題が 2 つ。ndeloof が [#14177 のインラインレビュー](https://github.com/docker/compose/pull/14177#discussion_r4096653359)（`model.go:49`）で「Two pre-existing issues here… worth a follow-up」と書いたもの。

1. `ListModels` の `err` を見ていない。失敗すると空のリストとして扱い、全モデルを pull しに行き、エラーも報告しない。`modelAPI` に移したとき（17ba6c718）に確認が抜けた。
2. 各 goroutine が外側の `err` に `PullModel` の結果を代入している。複数のモデルを pull するとデータ競合になり、pull していないモデルに `ConfigureModel` しうる。

## 修正内容

- `ListModels` のエラーを返す。
- `PullModel` のエラーを goroutine の中の変数（`if err := ...; err != nil`）に持つ。他の並列処理と同じ形。

## 変更ファイルとその内容

```
pkg/compose/model.go | 4 +- 2
```

単体テストは足していない。`ensureModels` は本物の `docker-model` プラグインを `manager.GetPlugin` で探すので、既存の単体テストから届かない。CI の unit テストは `-race` 無しなので、競合も CI では捕まらない。

確認は、偽の `docker-model` プラグイン（呼び出しを記録するだけ）と `-race` のビルドで行った:

| 場面 | 修正前 | 修正後 |
| ---- | ------ | ------ |
| `ls --json` が失敗する | 終了コード 0。両方 pull して作成まで進む | 終了コード 1、`error checking available models` |
| 2 つとも pull が要る | 終了コード 66、`DATA RACE` 1 件（`model.go:62`） | 0、競合なし |
