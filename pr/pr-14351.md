# PR #14351: test(formatter): keep escape sequences out of the go test output

https://github.com/docker/compose/pull/14351

- 状態（2026-10-18）: OPEN。レビュー待ち

## 問題

`cmd/formatter` の `TestRunHandlesKeysUntilContextIsDone` は成功しているのに、
gotestsum が毎回 `=== FAIL: cmd/formatter TestRunHandlesKeysUntilContextIsDone (unknown)` と `DONE … 1 failure` を出していた。

- 終了コードは 0 なので、CI のジョブ自体は成功する。ただし、Unit Test Summary には `failed = 1` と出る。main の green な run でも毎回出ていた。
- 実害として、thaJeztah が [#14339](https://github.com/docker/compose/pull/14339) で、この行を本物の失敗と取り違えかけた（本当の原因は別のテストだった）。
  CI の失敗を調べるたびに、人の時間を取る。

## 原因

1. テストは、キーボード操作の処理（`KeyboardManager.Run`）に `d`（デタッチ）キーを送る。
2. デタッチの処理の中で `clearNavigationMenu()` が呼ばれ、画面下のナビゲーションメニューを消すための ANSI エスケープシーケンス（`\x1b[0G\x1b[s\x1b7\x1b[u\x1b8`）を、**改行無しで** os.Stdout に書く。
3. Go のテストランナーは、テストが終わると同じ stdout に `--- PASS: ...` を書く。そのため、1 行が `<エスケープシーケンス>--- PASS: ...` になる。
4. gotestsum は「行頭が `--- PASS:` か」で結果を判定するので、この行を認識できず、結果の分からないテストとして `FAIL (unknown)` と数えていた。

このデタッチ時のメニューの消去は、[#14324](https://github.com/docker/compose/pull/14324)（10-10）で入った。

## 修正内容

- テストの間だけ、パッケージ変数 `disableAnsi` を true にし、`t.Cleanup` で false に戻す。
  `cmd/formatter/ansi.go` の ANSI を書く関数は、どれも最初に `disableAnsi` を見て、true なら何も書かずに return する。
- 書き方は、同じパッケージの `ansi_test.go` に合わせた。
- テストのコードだけの変更で、プロダクトのコードは変えていない。キー処理のロジックは、ANSI 出力の有無と関係なく、これまでどおりテストされる。

## 変更ファイルとその内容

```
cmd/formatter/shortcut_test.go | 5 +++++
```

- `cmd/formatter/shortcut_test.go`: `TestRunHandlesKeysUntilContextIsDone` の冒頭に、次の 5 行を追加。

  ```go
  // the detach key clears the navigation menu with escape sequences written to
  // os.Stdout, which would corrupt the `go test -v` output parsed by gotestsum
  disableAnsi = true
  t.Cleanup(func() { disableAnsi = false })
  ```

- 確認: CI と同じ gotestsum v1.13.0 で `-v -race` を付けて流すと、修正前は `DONE 12 tests, 1 failure`、修正後は `DONE 12 tests`。
