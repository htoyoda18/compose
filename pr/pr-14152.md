# PR #14152: feat(tracing): surface otel shutdown errors via --debug

https://github.com/docker/compose/pull/14152

## 問題

`cmd/cmdtrace/cmd_span.go` の `wrapRunE` 内で、コマンド終了時に呼ばれる
`tracingShutdown(ctx)`（トレーサーのflush/shutdown処理）のエラーが
`_ = tracingShutdown(ctx)` として常に握りつぶされていた。

OTLPエンドポイントの設定ミスや疎通不可などでトレース送信が失敗しても、
利用者側からはそれを診断する手段が一切なく、コードに手を入れて
インストルメントしない限り原因が分からない状態だった。

## 原因

`cmd_span.go` には `// TODO(milas): add an env var to enable logging from the
OTel components for debugging purposes` というTODOコメントが残っており、
デバッグ用の仕組みが未実装のまま放置されていた。

当初は専用の環境変数 `COMPOSE_OTEL_DEBUG` を新設する方向で実装したが、
レビュー（@glours）で「Composeには既に `--debug`/`-D` という汎用のデバッグ
切り替えがあり、他の箇所でもこの手のトレーシング診断情報はそこを通している。
新しい環境変数を増やすより、そちらに寄せた方がシンプルになるのでは」という
指摘を受けた。

調査の過程で、`internal/tracing` パッケージが `init()` 時に独自の
`otel.SetErrorHandler(skipErrors{})`（エラーを握りつぶすno-opハンドラ）を
登録していたことが判明。しかし `docker/cli` 側のプラグインフレームワーク
（`plugin.Run()`）が起動時に `otel.SetErrorHandler(debug.OTELErrorHandler)` を
呼び出しており、これは各パッケージの `init()` が全て実行された**後**に走るため、
Compose独自のハンドラは常に上書きされて一度も効いたことがなかった
（実バイナリでの呼び出し順序のトレースと挙動再現で確認済み）。

つまり:
- `internal/tracing` の独自 `otel.ErrorHandler`（`skipErrors`）は死んでいた
- OTel SDK/exporter起因のエラーは、実際には `docker/cli` 側の
  `debug.OTELErrorHandler` を通じて既に処理されていた
- 真に握りつぶされていたのは `wrapRunE` 内の `tracingShutdown(ctx)` の
  戻り値のみ

## 修正内容

- `COMPOSE_OTEL_DEBUG` 環境変数案は撤回し、既存の `--debug`/`-D` の仕組みに一本化
- `wrapRunE` で `tracingShutdown(ctx)` のエラーを `logrus.WithError(err).Debug(...)`
  に渡すよう変更。logrus自体のログレベルで `--debug`/`-D` によるゲーティングが
  かかるため、明示的な条件分岐は不要
- `internal/tracing` の独自 `otel.ErrorHandler`（`errors.go` の `skipErrors`）と、
  `tracing.go` の `init()` 内の `otel.SetErrorHandler(skipErrors{})` 呼び出しを
  完全に削除（`docker/cli` 側のハンドラに常に上書きされ、一度も効いていなかったため）

## 変更ファイルとその内容

```
cmd/cmdtrace/cmd_span.go   | 4 +++-  -3
internal/tracing/errors.go  | 0 +29 (削除)
internal/tracing/tracing.go | 0 +2  (削除)
```

- `cmd/cmdtrace/cmd_span.go`: `logrus` importを追加し、`tracingShutdown(ctx)` の
  戻り値エラーを `logrus.WithError(err).Debug("otel: shutdown error")` でログ出力
- `internal/tracing/errors.go`: ファイルごと削除（`skipErrors` no-opハンドラ）
- `internal/tracing/tracing.go`: `init()` 内の `otel.SetErrorHandler(skipErrors{})`
  呼び出しを削除
