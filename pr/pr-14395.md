## 問題

前景の `docker compose up` が自分でアプリを止めるとき、`-t/--timeout` が効いていなかった。

- 対象は 2 つの場面。Ctrl+C を押したときと、`--abort-on-container-exit` / `--exit-code-from` で、どれかのコンテナが終了して全体を止めるとき。
- `-t` を無視して、サービスごとの `stop_grace_period`（未指定ならエンジンの既定）だけ待っていた。ヘルプには、`-t` は「when attached」の停止のタイムアウトと書かれている。
- CI でよく使う `up --abort-on-container-exit --exit-code-from tests -t 2` の後片付けが、指定より遅くなる。
- 同じプロジェクトで `docker compose stop -t 2` を実行すれば効く。Compose v1 では `up` でも効いていた。

## 原因

- `pkg/compose/up.go` の 2 つの関数が、`u.stop` に渡す `api.StopOptions` に `Timeout` を書いていなかった。Go の既定値の nil になり、`stop_grace_period` が使われていた。
  - `stopApplication`: Ctrl+C と、コンテナの終了をきっかけに全体を止めるとき。
  - `stopLateStarter`: 停止が始まった後に起動してきたサービスを止めるとき。
- `-t` の値は、すでに `u.options.Create.Timeout` に入っていた。使われていなかっただけ。
- [pr-14358.md](./pr-14358.md) の「関連して気付いたこと」に書いた、「書き忘れたフィールドが Go の既定値になる」漏れの 1 つ。

## 修正内容

- 2 つの関数の `api.StopOptions` に `Timeout: u.options.Create.Timeout` を足した。
- `-t` を指定しないときは nil のままなので、これまでと同じく `stop_grace_period` が使われる。

- `pkg/compose/up_test.go`: `TestUpSessionStopsWithUpTimeout` を追加。
  - `stopApplication` と `stopLateStarter` の 2 つのサブテスト。`Create.Timeout` に 2 秒を入れた `upSession` で止めて、mock の `ContainerStop` に渡った `ContainerStopOptions` の `Timeout` が `-t` の値になっていることを確かめる。
  - 修正前は、どちらのサブテストも `Timeout` が空で失敗した。
- `pkg/e2e/cascade_test.go` と testdata: Scenario DSL で `TestCascadeStopHonorsTimeout` を追加。
  - `app` は SIGTERM を処理しない `sleep infinity` で、`stop_grace_period: 2m`。`tests` は 1 秒後に `exit 3`。
  - `up -t 1 --abort-on-container-exit --exit-code-from tests` が 60 秒以内（`Within`）に終了コード 3 で終わり、`app` が exited になることを確かめる。
  - 修正前は 60 秒の上限に当たり、修正後は約 3.5 秒で終わる。
  - Ctrl+C も同じ `stopApplication` を通るが、Scenario DSL はシグナルを送れないので、単体テストだけで確かめた。そのことを PR の本文に書いた。
