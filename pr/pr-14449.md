# PR #14449: fix(down): keep volumes other services use on down -v with services

https://github.com/docker/compose/pull/14449

- 状態（2026-11-05）: OPEN。ndeloof が 11-04 に APPROVED。CI はすべて pass。急がない指摘が 2 つ（下）

## 問題

compose ファイルがある状態で `down -v web` を実行すると、止めるコンテナは web だけなのに、消すボリュームは web と**その依存先**（db など）のもの全部になる。
依存先のコンテナが動いていれば「使用中」で守られるが、無ければ（全体を `down` した後など）消える。データ消失（5.0.1 と main）。

再現（5.0.1）: `up -d` → db にデータを書く → `down` → `down -v web` → `Volume vm-scope_dbdata Removed`。

## 原因

- `cmd/compose/down.go:80` の `projectOrName(services...)` から、`internal/projectloader/loader.go:150` の `WithSelectedServices` と `:157` の `WithoutUnnecessaryResources` で、モデルが「指定したサービスとその依存先」に絞られる。
- `pkg/compose/down.go` の `ensureVolumesDown` は、絞られたモデルのボリュームを全部消す。
- 補足: `-p` だけで実行したときは、依存元も止める（`WithRootNodesAndDown`）。指定の仕方で挙動が違う（[compose-lifecycle.md の 1](../document/concepts/compose-lifecycle.md#1-depends_on)）。
- #10552（2023）のレビューで milas が「Volumes and --rmi flag are problematic」と指摘していたが、採られなかった。

## 修正内容

issue で 2 案を出し、(a) を選んだ。

- (a) 実際に止めるサービスだけが使うボリュームに限る ← 採用
- (b) サービスを指定したときは、`-v` と `--rmi` を拒否する（XS だが挙動が変わる。#10552 で milas が出した案）

`down` は止めるサービス（指定したものと、その依存元）を記録する。サービスを指定したときは、`ensureVolumesDown` が、他のサービス（選択で無効になったものも含む）が使うボリュームを飛ばす。`reconcile.go` の `volumeConsumers` を再利用するので、`volumes_from` もたどる。サービスを指定しない `down -v` は変わらない。
