# PR #14053: fix(display): wire --dry-run flag into progress writers

https://github.com/docker/compose/pull/14053

## 問題

`cmd/display/tty.go:56` の FIXME(ndeloof) から派生。`--dry-run` を付けて実行しても、
TTY / Plain / JSON いずれの progress 出力にも "DRY-RUN MODE" 表示が出ない。

## 原因

`ttyWriter` / `plainWriter` / `jsonWriter` はいずれも `dryRun bool` フィールドを持ち、
出力時にこれを見て "DRY-RUN" prefix を付けるロジックはあった。しかし各構造体を生成する
コンストラクタ `display.Full()` / `display.Plain()` / `display.JSON()` には
そもそも dryRun を渡す引数がなく、外から `true` にする手段が存在しなかった（常に `false`）。

`cmd/compose/compose.go` の `--dry-run` フラグ自体（ローカル変数 `dryRun`）は
`selectEventProcessor()` が呼ばれる時点で既にパース済みだったので、実行順序の問題ではなく
単純な配線漏れだった。

## 修正内容

- `display.Full(out, info, detached, dryRun bool)` / `display.Plain(out, dryRun bool)` /
  `display.JSON(out, dryRun bool)` に `dryRun` 引数を追加し、各構造体フィールドへ設定
- `cmd/compose/compose.go` の `selectEventProcessor()` にも `dryRun` を追加し、
  パース済みの `--dry-run` フラグ値をそのまま各コンストラクタへ橋渡し
- `cmd/display/tty.go` の FIXME コメントを削除

## 追加したテスト

unexported フィールドは `display` パッケージ内からしか検証できないため、
コンストラクタが `dryRun` を正しく配線することを確認するテストを同パッケージ内に追加：

- `cmd/display/plain_test.go`（新規）: `Plain(out, true/false)` で DRYRUN_PREFIX の有無を確認
- `cmd/display/json_test.go`: `JSON(out, true)` の出力JSONで `dryRun` が反映されることを確認
- `cmd/display/tty_test.go`: `Full(out, info, false, true)` が `ttyWriter.dryRun` を true にすることを確認

`cmd/compose/compose_progress_test.go` は `selectEventProcessor` のシグネチャ変更に
引数追加で追従したのみ（戻り値の型しか見ておらず、内部フィールドは別パッケージのため
未検証・未追加）。
