# PR #14363: fix(watch): ignore .git at any depth inside the watched path

https://github.com/docker/compose/pull/14363

- 状態: **2026-10-20 にマージ**（ndeloof が APPROVED してマージ）。issue [#14362](https://github.com/docker/compose/issues/14362) もクローズ

## 問題

`docker compose watch` は `.git/` を必ず無視するつもりの作りなのに、watch のパスの中にある `.git` の変更を拾っていた。

- `sync` のルールでは、git を操作するだけ（空のコミットでも）で、`.git` の中身がコンテナに同期された。
- `rebuild` のルールでは、ソースを 1 回編集するだけで、**再ビルドが止まらなくなった**（30 秒で 30〜40 回）。
  リポジトリの直下に compose.yaml を置き、`path: .` で監視する、いちばんよくある構成で起きる。

## 原因

- `pkg/compose/watch.go` の `getWatchRules` が、無視のルールを `watch.NewDockerPatternMatcher("/", []string{".git/"})` で作っていた。
  パターンは基準のパスとつなげられるので、これは `/.git/` になり、ファイルシステムのルート直下の `.git` にしか一致しない。
- 監視中のイベントはフルパス（`/home/me/project/.git/index` など）なので、一致しなかった。
- rebuild が止まらない仕組み: buildx はビルドのたびに、来歴情報（provenance）のために git の状態を読み、そのときに `.git` を書き換える。
  それを watch が新しい変更として拾い、また再ビルドする、を繰り返していた。
  `BUILDX_GIT_INFO=0` にするか、`.dockerignore` に `.git` を書くと止まることで、原因を確かめた。

## 修正内容

- パターンを `**/.git` に変えた。どの深さの `.git` とその中身にも一致し、`.gitignore` や `.github/` には一致しない。
- 初回の同期（`initialSync`）にも同じパターンがあるが、こちらはファイル名だけ（`.git`）で照合するので、今のままで正しく除外できていた（upstream main で確認）。動いている箇所なので、変えていない。

## 変更ファイルとその内容

```
pkg/compose/watch.go      |  2 +-
pkg/compose/watch_test.go | 29 +++++++++++++++++++++++++++++
```

- `pkg/compose/watch.go`: パターンの 1 行だけ。コメントは足していない（`**/` を見れば、どの深さにも一致させることは読み取れるため）。
- `pkg/compose/watch_test.go`: 表形式のテスト `TestWatchRules_IgnoreGitDirectoryAtAnyDepth` を追加。
  - `getWatchRules` で作ったルールの `Matches` を使い、`.git`、`.git/index`、`.git/objects/ab/cdef`、深い場所の `vendor/lib/.git/HEAD` が無視されることを確かめる。
  - 逆に、`main.go`、`.gitignore`、`.github/workflows/ci.yml` は無視されないことも確かめる。
  - パスは `t.TempDir()` と `filepath.FromSlash` で組み立て、Windows でも形が崩れないようにした。
  - コメントは、同じファイルの `// #13725: ...` に揃えた 1 行（`// #14362: the .git ignore rule only matched /.git, not .git inside the watched path.`）。

## 確認したこと

- 新しいテストは、修正を外すと `.git` の 4 ケースだけが失敗し、修正後は通る。
- 実機（ブランチのバイナリ）: ソースを 1 回編集すると再ビルドは 1 回、空のコミットでは 0 回（修正前は 30 秒で 40 回）。
- watch の e2e 7 本、`go test ./pkg/compose/ ./cmd/...`、`docker buildx bake lint` が通る。

## 経緯と学び

- 最初は「`.git` がフィルタされず、無駄な同期や再ビルドが走るだけ」だと思っていた。調べを進めると、rebuild では buildx との組み合わせでループすると分かり、issue の主題をそちらに変えた。issue には、その経緯を説明するコメントも付けた。
- 検証で 1 度誤った: watch のログを監視対象のディレクトリの中に書くと、それ自体が再ビルドを起こす。ログは必ず監視の外に書く。
- レビューの指摘は無く、そのまま承認された。コードのコメントを最小限にし、2 か所のうち壊れている 1 か所だけを直したことで、差分が小さく読みやすかったのが効いたと思われる。
- 同じ「watch が止まらない」種類の問題がもう 1 つ見つかっている（許可リスト型の `.dockerignore`。[next-tasks.md の N6](../document/tracking/next-tasks.md#n6-許可リスト型の-dockerignore-で-watch-が無視のルールを全部捨てる)）。
