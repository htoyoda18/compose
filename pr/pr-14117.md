# PR #14117: fix(watch): exclude Dockerfile and compose files from initial sync

https://github.com/docker/compose/pull/14117

## 問題

`pkg/compose/watch.go` の `initialSync` 関数のdocコメントは「ignores develop.watch.ignore,
**Dockerfile, compose files**, bind mounted paths and .git」と謳っているが、実際には
`docker compose watch` の初回同期で `Dockerfile` や `compose.yaml` がコンテナ内にコピーされてしまう。

これが問題になる理由は主に2つ:
- **情報漏洩リスク**: `compose.yaml` にはポート番号や環境変数、シークレット参照などの
  オーケストレーション情報が書かれていることが多く、それがアプリのランタイムコンテナ内に
  そのまま置かれてしまう
- **本来の設計意図との不整合**: Dockerfile/compose.yamlはビルド・オーケストレーション用の
  ファイルであり、アプリケーションのソースコードではない。これらがアプリの作業ディレクトリに
  紛れ込むと、コンテナ内のツール（linter, ビルドツール等）が予期せずそれらを読み込んだり、
  意図しないファイル汚染が起きる

## 原因

`initialSync` 内に残っていた `// FIXME .dockerignore` コメントを起点に調査したところ、
2025-01の多サービスwatch対応リファクタ（commit `ed10804e0`, [PR #12469](https://github.com/docker/compose/pull/12469)）で、
それまで存在していた `Dockerfile` / `*compose*.y*ml` 除外専用のmatcherが、代替なしに削除されていたことが判明した。

以降は `.dockerignore` 由来のmatcherと `EphemeralPathMatcher()`（vim/emacs等のエディタ一時ファイル用）
のみが `ignoreInitialSync` を構成しており、どちらも `Dockerfile` や `compose.yaml` をファイル名として
除外する機能を持たない。一時テストで `initialSyncDirectory` を直接呼び出し、`Dockerfile` と `compose.yaml`
が実際に同期対象に含まれてしまうことを再現・確認した。

なお継続監視ループ側（`getWatchRules`）はそもそも元のFIXMEコメントの対象外であり、ドキュメント上も
このexclusionは`initialSync`にしか約束されていないため、修正はそちらに限定した。

## 修正内容

- `initialSync` 内に `dockerFileIgnore` matcherを再導入し、`ignoreInitialSync` のcomposite matcherに追加
- 初回コミットでは `"Dockerfile", "*compose*.y*ml"` という固定パターンで実装
- レビュー後のフォローアップコミットで、より正確なパターンに改善：
  - `compose-spec/compose-go` の `cli.DefaultFileNames` / `cli.DefaultOverrideFileNames` を使い、
    `compose.yaml` 以外の標準ファイル名（`docker-compose.yml` 等）やoverrideファイルも網羅
  - `service.Build.Dockerfile` が指定されている場合、そのカスタムDockerfile名（`filepath.Base` で
    サブディレクトリを除いたベース名）も除外対象に追加

    ようにサブディレクトリ配下にある場合も、basename一致で正しく除外されることを確認
