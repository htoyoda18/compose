# PR #14358: fix(run): keep a recreated dependency's anonymous volumes

https://github.com/docker/compose/pull/14358

- 状態（2026-10-18）: OPEN。レビュー待ち
- issue: [#14357](https://github.com/docker/compose/issues/14357)（自分で立てた。status/0-triage）

## 問題

`docker compose run` が依存サービスを作り直すと、新しいコンテナが、古いコンテナの匿名ボリュームを引き継がず、新しい空のボリュームを付けていた。

- postgres や mysql のように、イメージが `VOLUME` を宣言している依存サービスでは、データが消えたように見える。
- 同じ状況でも `docker compose up` なら引き継ぐので、データは残る。
- データそのものは消えていない。古いボリュームは dangling（どのコンテナからも使われない状態）で残るので、手で取り戻せる。ただし `docker volume prune` を実行すると消える。
- リリース版（Docker Compose 5.0.1）でも再現する。

## 原因

- `run` は、依存サービスを `startDependencies`（`pkg/compose/run.go`）で `create()` → `start()` して起動する。
- そのとき渡す `api.CreateOptions` に `Inherit` を書いていなかったので、Go の既定値の `false` になっていた。
  - `Inherit` は「作り直すとき、古いコンテナの匿名ボリュームを新しいコンテナに付け直すか」を表すフィールド。
  - `up` は `Inherit: !noInherit`（`-V` / `--renew-anon-volumes` を付けたときだけ false）、watch の rebuild は常に `Inherit: true` を渡している。
- plan engine では、`planRecreateContainer` が `Inherit` が true のときだけ、古いコンテナを `Inherited` として作成の操作に渡す。それを見て、`buildContainerMountOptions` が匿名ボリュームを付け直す。
- 履歴を見ると、v2 で `run` が一度も `Inherit` を渡していなかったので、最近の退行ではない。v1 は引き継いでいたので、関連する issue [#13769](https://github.com/docker/compose/issues/13769) の「v1 では起きなかった」とも合う。
- [#14144](https://github.com/docker/compose/pull/14144)（ndeloof）は `run --no-recreate` を足して、作り直しそのものを避けられるようにした。ただ、作り直しが起きたときにデータが見えなくなる原因は残っていた。

## 修正内容

- `startDependencies` で `Inherit: true` を渡す。
- `run` には `--renew-anon-volumes` のようなフラグが無く、利用者が「新しくしたい」と指定する手段が無いので、watch と同じく常に true にした。理由はコメントに書いた。
- 影響が出るのは、`run` が依存サービスを**作り直すとき**だけ。新しく作るとき、`--no-recreate` のとき、設定が変わっていないときは何も変わらない。`run` で起動する oneoff のコンテナ自体は、この関数を通らない。

## 変更ファイルとその内容

```
pkg/compose/run.go                                                    |  3 +++
pkg/e2e/compose_run_test.go                                           | 18 ++++++++++
pkg/e2e/testdata/TestComposeRunInheritsAnonymousVolumes/compose.yaml  | 18 ++++++++++ (新規)
```

- `pkg/compose/run.go`: `startDependencies` の `api.CreateOptions` に、`Inherit: true` と 2 行のコメントを追加。
  （`Inherit:` だけコロンの位置が揃っていないのは、コメント行で gofmt の整列のまとまりが切れるため）
- `pkg/e2e/compose_run_test.go`: Scenario DSL で `TestComposeRunInheritsAnonymousVolumes` を追加。似た内容の `TestComposeRunNoRecreate` のすぐ後に置いた。
  1. `TAG=one` で `run task` → `dep` が running
  2. `exec dep` で `/data/marker` に `kept` を書く
  3. `TAG=two` で `run task` → `dep` が作り直され（`Recreated`）、`cat /data/marker` が `kept` を出す（`ExecOutputContains`）
  - **データはテストから書く**。コンテナ自身に書かせると、新しい空のボリュームでも作り直し後にまた書かれ、バグがあってもテストが通ってしまうため。
  - `Recreated("dep")` も確かめて、「作り直しが起きた上で、データが残っている」ことを保証している。
- `pkg/e2e/testdata/TestComposeRunInheritsAnonymousVolumes/compose.yaml`: `TestComposeRunNoRecreate` の testdata に、匿名ボリューム `volumes: - /data` を足したもの。
  環境変数 `TAG` を変えて `dep` の config hash を変え、作り直しを起こす。
  ビルドの要らない `volumes: - /data` を選んだ。イメージの `VOLUME` でも同じ処理（`buildContainerMountOptions`）で引き継がれ、それは手元の再現手順で別に確かめた。

## 確認したこと

- 修正を外したバイナリでは、新しいテストが `cat: can't open '/data/marker'` で失敗する。修正後は通る。
- `run` まわりの e2e 19 本、`go test ./pkg/compose/ ./cmd/...`、`docker buildx bake lint`（0 issues）が通る。
- `make e2e-compose` の全体の実行では 3 件が失敗したが、どれも `run` を使わないテストで、今回の変更とは関係ない。
  - `TestImageVolumeRecreateOnRebuild`: upstream main でも同じ「file name too long」で失敗する（この環境の問題）。
  - `TestRestartWithDependencies` / `TestNetworkConfigChanged`: 単独で流すと、修正の有無にかかわらず、繰り返し流しても通る。並列で流したときの干渉と推定（`TestNetworkConfigChanged` は subnet `192.168.0.0/16` が、ほかのネットワークと重なった）。
