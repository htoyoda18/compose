# go.md を読んで出た疑問 Q&A

[go.md](./go.md) を読んでいて出た疑問への短い回答。

← [document 一覧](../README.md)

## 1. goroutine leak とは

- 起動した goroutine が**永遠に終わらず残り続ける**こと。GC は動いている goroutine を回収しないので、メモリと、その goroutine が掴んでいるリソースが漏れ続ける。
- 典型的な原因は、誰も受信しない channel への送信（または誰も送信しない channel からの受信）で止まったままになるケースと、終了条件（`ctx.Done()`）を見ないループ。
- 防ぎ方は「起動した goroutine を誰がいつ終わらせるか」を必ず決めること。`select` で `ctx.Done()` も待つ、channel を閉じる側を決めておく、`errgroup` で `Wait()` する、など。

## 2. buffered / unbuffered channel の違い

- **unbuffered**（`make(chan int)`）は送信側と受信側が**同時にそろうまで両方ブロック**する。値の受け渡しと同時に「相手が受け取った」という同期にもなる。
- **buffered**（`make(chan int, 3)`）は容量ぶんまで、受信を待たずに送信できる。満杯なら送信が、空なら受信がブロックする。
- buffer は速度差の吸収や同時実行数の上限（セマフォ）に使う。ただし「とりあえず buffer を付ければ詰まらない」は危険で、詰まりや leak が後回しになるだけのことが多い。

## 3. 他の言語ではキャンセルをどう伝えるか

- **C# / .NET**: `CancellationToken` を引数で引き回す。Go の `context` とほぼ同じ発想。**JavaScript**: `AbortController` / `AbortSignal` を `fetch` などに渡す。
- **Kotlin**（コルーチン）・**Swift**（`Task`）・**Python**（`asyncio` の `Task.cancel()`）: 親子関係のあるタスク木の中で、親をキャンセルすると子にも自動で伝わる（構造化並行性）。値を引数で渡す必要がない。
- **Java**: 従来はスレッドへの `interrupt()` や `Future.cancel()`。いずれもキャンセルは協調的で、呼ばれた側がフラグを確認しないと止まらない点は Go と同じ。

## 4. Go 流の設計思想（もう一歩踏み込んで）

- **インターフェースは使う側が定義する**: Go は implements 宣言なしでメソッドが合えば満たせる（構造的型付け）。だから実装側が大きな interface を公開するのではなく、呼び出し側が「自分が必要な 1〜2 メソッド」だけの小さな interface を定義する（`io.Reader` が代表例）。合言葉は「Accept interfaces, return structs」。
- **継承より合成**: クラス継承はなく、構造体の埋め込みと小さな interface の組み合わせで振る舞いを作る。
- **明示的であることを優先**: エラーは例外ではなく戻り値で返して、その場で扱う。並行処理では「メモリを共有して通信するな、通信してメモリを共有せよ」（channel）。機能を絞った言語で、誰が書いても似たコードになることを重視している（`gofmt` で整形も統一される）。

## 5. go.mod と go.sum の違い

- **go.mod** は「このモジュールの名前、Go のバージョン、**どの依存をどのバージョンで使うか**」を宣言する、人が読んで編集するファイル。npm でいう `package.json`。
- **go.sum** は各依存モジュール（間接依存も含む）の**中身のハッシュ値**の記録。ダウンロードしたコードが改ざんされていないかを検証するためのもので、手で編集はしない。
- ただし npm の `package-lock.json` とは違い、使うバージョン自体は go.mod だけで決まる（Minimal Version Selection）。go.sum は「そのバージョンの中身が本物か」を保証するだけ。両方コミットする。
