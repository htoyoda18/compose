# networking.md を読んで出た疑問 Q&A

[networking.md](./networking.md) を読んでいて出た疑問への短い回答。

← [document 一覧](../README.md)

## 1. ネットワークドライバとは

- Docker のネットワーク（`docker network create` で作るもの）を、**実際にどういう仕組みで実現するかを決める部品**。「コンテナ同士・外部とつなぐ」という同じ要求に対して、実装の方式をドライバとして差し替えられるようになっている。
- たとえば `bridge` はホスト内に仮想スイッチを作って veth でつなぐ。`overlay` は複数ホストの間をトンネルで結ぶ。`macvlan` はコンテナに物理ネットワーク上の MAC アドレスを持たせる。`host` は分離せず、ホストのネットワークをそのまま使う。
- Compose の `networks:` で `driver:` を省略すると `bridge` になる。

## 2. パケットフィルタリングとは

- ネットワークを流れるデータの小包（パケット）を 1 つずつ見て、**通す・捨てる・書き換える**をルールで決める仕組み。いわゆるファイアウォールの中身。
- ルールは「送信元 / 宛先の IP アドレス・ポート番号・プロトコル」などの条件で書く。たとえば「外から 22 番ポートへのパケットは捨てる」など。
- Linux ではカーネルの netfilter がこれを行い、iptables / nftables はそのルールを設定するためのツール。Docker はコンテナの通信を制御するために、このルールを自動で書き込んでいる。

## 3. NAT とは

- Network Address Translation の略で、パケットが通過するときに**IP アドレス（やポート番号）を書き換える**仕組み。
- 家庭のルーターが典型例。家の中の機器はプライベートな IP アドレスしか持たないが、外に出るときにルーターのグローバル IP アドレスに書き換えるので、インターネットと通信できる。
- Docker では 2 方向で使っている。コンテナから外へ出るときはホストのアドレスに書き換える（コンテナはプライベートなアドレスしか持たないため）。`-p 8080:80` は逆向きで、ホストの 8080 番に来たパケットの宛先を、コンテナの IP アドレスの 80 番に書き換えている。

## 4. IP アドレスはコンテナごとに割り振られているのか

- そのとおり。正確には**コンテナが参加しているネットワークごとに 1 つずつ**割り振られる。2 つのネットワークに参加しているコンテナは、IP アドレスを 2 つ持つ。
- アドレスは、Docker がネットワークごとに持つ範囲（例: `172.18.0.0/16`）から自動で払い出される。コンテナを作り直すと変わりうるので、IP アドレスを決め打ちせず、サービス名（内蔵 DNS）で通信するのが普通。
- 例外として、`network_mode: host` のコンテナは自分の IP アドレスを持たず、ホストのものをそのまま使う。

## 5. MAC アドレスと IP アドレスは、識別するレイヤーが違うのか

- その認識で合っている。MAC アドレスは**レイヤー 2（データリンク層）**の識別子で、同じネットワーク（同じスイッチの先）の中で「隣の機器」に届けるために使う。IP アドレスは**レイヤー 3（ネットワーク層）**の識別子で、ルーターをまたいで「最終的な宛先」に届けるために使う。
- 遠くに送るときも、IP アドレスは最後まで変わらない（NAT を除く）。一方で MAC アドレスは、ルーターを 1 つ越えるたびに「次に渡す相手」のものに付け替えられる。宅配でいうと、IP アドレスは最終的な届け先の住所、MAC アドレスは次の中継所の名前に近い。
- IP アドレスから MAC アドレスを調べるのが ARP。コンテナも bridge ネットワーク上では、それぞれ自分の MAC アドレスと IP アドレスを持っている。
